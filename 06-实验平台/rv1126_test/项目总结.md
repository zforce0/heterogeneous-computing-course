# rv1126_test 项目总结

> RV1126B 板端双相机（红外 + 可见光）拉流 + YOLOv8 NPU 推理 + 双模态差分显著级联检测。
>
> 本文档综合 [实现思路.md](实现思路.md)（一/二期设计与板端实测）、[RV1126B双光差分显著+YOLO级联Demo实现方案.md](RV1126B双光差分显著+YOLO级联Demo实现方案.md)（三期方案）、[SSH板端初始化配置.md](SSH板端初始化配置.md)、[USB带宽约束分析.md](USB带宽约束分析.md)、[dual_demo/README.md](dual_demo/README.md)、[dual_demo/docs/ir_temp_probe_report.md](dual_demo/docs/ir_temp_probe_report.md) 整理。

## 1. 项目功能

项目按三个阶段演进，根目录程序承载一/二期，`dual_demo/` 承载三期：

### 1.1 一期：可见光 YOLOv8 实时推理（`rv1126_yolov8_demo`）

- 可见光 USB 相机（`1d6c:0103`，V4L2 MJPG 640×480@30）持续取流，主线程每次取**最新一帧**送 YOLOv8m RKNN 模型（NPU，~71ms/帧）推理；
- 检出目标时打印类名/置信度/坐标、画框存图，`output/` 滚动只保留最近 10 张；
- 全链路分段计时（cap/dec/age/pre/set/npu/get/post/save/total），Ctrl+C 退出打印 `[STAT]` 统计（avg/min/max/p95）；
- 模型路径作为第一个命令行参数（与 `yolov8_detect_C_demo` 用法一致）。

### 1.2 二期：双相机同时拉流（红外优先）

| 相机 | USB ID | 采集方式 | 格式/分辨率 | 用途 |
|---|---|---|---|---|
| 红外（最高优先级） | `0bda:5840` | **闭源 SDK（libusb 直连，不走 V4L2）** | 256×384 YUY2 组合流 → 切出 256×192 图像 @25fps | 拉流 + 帧率统计 |
| 可见光 | `1d6c:0103` | V4L2 MJPG | 1280×720@25 | 拉流 + YOLO 推理 |

- 三线程架构：IR 采集 / VIS 采集 / 主线程推理，互不阻塞；推理只消耗可见光最新帧（~14fps），不拖累红外 25fps；
- 检出时**最近邻配对成对保存** `_vis.jpg`（带框 1280×720）+ `_ir.jpg`（原始 256×192），对齐误差典型 ≤20ms，按对滚动保留 10 对；
- 每 2s 打印 `[FPS] ir: cur=25.0 avg=24.9 | vis: ...`，Ctrl+C 退出汇总两路帧数/帧率与推理/存图统计。

### 1.3 三期：双模态差分显著 + YOLO 级联（`dual_demo/rv1126_dual_demo`）

**一句话：红外只做"看这里"（差分显著提名），可见光只做"认"（crop → YOLO 确认），把 NPU 调用从逐帧全图压缩到事件驱动。**

```
IR 线程 ──► IR ring (256×192 Y16→℃ 温度矩阵 + 时间戳)
                             │ 最近邻配对 (delta ≤ 40ms)
VIS 线程 ► VIS ring (VIS BGR + 时间戳)
                             ▼
              显著线程 (CPU/NEON, 新增核心)
              T → S_tir (FT 偏离背景)
              G↓256×192 → S_rgb
              各自 P99 归一化 → 四象限判定
              → 闭运算 → 连通域 → 提名属性包(温度/显著性/时序/健康)
                             │ 有界队列(丢弃最旧, 不反压采集)
                             ▼
              主线程 (NPU): crop(+3倍margin) → letterbox → YOLO 确认
              → events.jsonl + 六宫格图 + 成对存图
```

- **四象限**：①热显著+视觉平淡（巡检提名主角）②双显著（庭院/活体提名）③热不可知（降级交 RGB 兜底，绝不判死，对应 thermal crossover）④背景（零输出）；
- **真实测温**（情形 A）：下半段为 Y16 定点温度矩阵，`℃ = raw/64 − 273.15`，THT 阈值带物理量纲（`T_bg_mode + 3.0K`）；提名输出 `t_max / t_ref / delta_t / t_lower_bound / t_true_est`；
- **时序维**（活体判据）：`dT/dt` 滑动拟合 + `micro_motion` 帧间差 + 质心最近邻关联（区分活体 vs 晒热岩石）；
- **优雅降级**：热交叉（场景热对比度 < `--c-min`）/ NUC 冻结 / 遮挡时自动 `[DEGRADE]` 切逐帧全图 YOLO，恢复后 `[RECOVER]` 切回级联；
- **判决指标**（无需标注数据）：`FAR = 1 − Σq1/Σtir_only ≥ 0.50`、`NPU 调用压缩比 ≤ 0.05`，退出 `[STAT]` 以 `>>>` 行输出；
- 输出物：`events.jsonl`（每提名一行，温度/显著性/时序/健康/语义字段）、`output/viz_*.jpg` 六宫格（VIS+框 / IR JET 伪彩 / S_rgb / S_tir / 差分图 / 四象限着色，留 10 张）、成对检测图；
- 运行模式：`--mode auto|cascade|baseline`（baseline 为逐帧全图 A/B 对照）、`--card inspect|yard|all`、`--probe-temp N`（温度探针，不加载模型）。

### 1.4 与参考项目的关系

- 推理链路（`lib/yolov8*.cpp` + `include/rknn_api.h` 等）拷贝自 `yolov8_detect_C_demo`；
- 采集链路（`visible_camera` / `mjpeg_decoder` / `ir_camera`）精简移植自 `twocameraOnMAC`；
- aarch64 红外闭源库取自 `twocameraOnMAC/test/camera_capture_test/build/libs/` 备份。

## 3. 本地启动（开发机）

**本地（x86 开发机）只能编译，不能运行**——程序依赖板端 NPU（`/dev/rknpu`）、`librknnrt` 2.3.2、板端 OpenCV 4.6 与两个 USB 相机。

### 3.1 板端编译（首选，零环境搭建）

板端 g++ 13.3 + OpenCV 4.6 + libjpeg 开发文件齐全，`build.sh` 检测 `uname -m == aarch64` 后直接本机编译：

```bash
# 方式一：本机一键部署（同步源码+模型 → 板端编译）
./deploy.sh                    # 默认 root@192.168.3.252，可传参覆盖
# 板端启动：
ssh root@192.168.3.252         # 密码 <REDACTED>
cd /userdata/rv1126_test && ./run.sh          # 根目录一/二期程序
cd /userdata/dual_demo   && ./run.sh          # 三期级联 demo

# 方式二：源码已在板上，板上直接编译
cd /userdata/rv1126_test && bash build.sh
```

### 3.2 本地交叉编译（备选，需一次性搭 sysroot）

`build.sh` 在非 aarch64 机器上会使用 `~/configs/cross.cmake` 工具链（该文件本机缺失，需自建）：

```cmake
set(CMAKE_SYSTEM_NAME Linux)
set(CMAKE_SYSTEM_PROCESSOR aarch64)
set(CMAKE_C_COMPILER   aarch64-linux-gnu-gcc)
set(CMAKE_CXX_COMPILER aarch64-linux-gnu-g++)
set(CMAKE_SYSROOT  $ENV{HOME}/sysroots/rv1126b)
```

sysroot 从板端拉取（rsync `/usr/include`、`/usr/lib`、`/lib/aarch64-linux-gnu`，详见 实现思路.md §5）。本机交叉 gcc 15 与板端 Ubuntu 24.04 (gcc13) 运行库 ABI 向后兼容。

### 3.3 板端 SSH 初始化（首次需在板端本地终端执行）

见 [SSH板端初始化配置.md](SSH板端初始化配置.md)：`sshd_config` 开启 `PasswordAuthentication yes` + `PermitRootLogin yes` 后 `systemctl restart sshd`。板端 IP 可能变化（曾用 192.168.3.248 → 192.168.3.252），`deploy.sh` 第一个参数可指定。

## 4. RV1126B 上的启动

### 4.1 板端环境（实测确认）

| 项目 | 结果 |
|---|---|
| 板卡/系统 | EASY-EAI-NANO-TB，aarch64，Ubuntu 24.04，内核 6.1.141 |
| NPU | RKNPU driver v0.9.8，`librknnrt.so` **2.3.2**（`/usr/lib` 与 `/oem/usr/lib`） |
| OpenCV / libjpeg | 4.6.0 / libjpeg-turbo（板端自带） |
| 编译器 | 板端 g++ 13.3.0（可直接编译） |
| 相机 | 红外 `0bda:5840`、可见光 `1d6c:0103`，**分挂两个独立 USB 控制器**（Bus 001 USB2.0 / Bus 004），节点号随重启漂移 → 程序按 VID/PID 自动探测，不写死节点 |

### 4.2 启动命令

```bash
# 根目录程序（一/二期：双相机拉流 + 可见光 YOLO 推理 + 成对存图）
cd /userdata/rv1126_test
./run.sh                          # 默认: IR 256x192@25 + VIS 1280x720@25
./run.sh -W 640 -H 480            # 降低可见光分辨率
./run.sh -d /dev/videoN           # 手动指定可见光节点

# dual_demo（三期：差分显著级联）
cd /userdata/dual_demo
./run.sh                                          # 默认 auto 模式 + inspect 卡
./build/rv1126_dual_demo ./yolov8m_rv1126b.rknn --help   # 全部参数
./build/rv1126_dual_demo ./yolov8m_rv1126b.rknn --probe-temp 100   # 温度探针
./build/rv1126_dual_demo ./yolov8m_rv1126b.rknn --mode baseline    # 逐帧 A/B 对照
```

- `run.sh` 特性：二进制缺失自动编译；程序因相机打开失败退出（退出码 3）时自动重试（`RETRIES=15` 次 / `INTERVAL=3s`）；设备还在总线上做 `authorized 0→1` 重枚举，设备消失则重置 USB Hub（`HUB_RESET=0` 可关闭）；`trap '' HUP` 防 SSH 闪断误杀。
- **启动顺序**：默认红外先出流、确认 25fps 后再启可见光（`ir-first`；两路 USB 独立后已非硬约束，dual_demo 提供 `--start-order parallel`）。
- 关键日志：`[FPS]`（每 2s 两路帧率）、`[SAL]/[EVT]/[NPU]/[SAVE]`（级联提名链路）、`[DEGRADE]/[RECOVER]`（降级）、`[STAT] >>> FAR / >>> NPU calls`（退出判决指标）。
- 输出物：`events.jsonl`、`output/viz_*.jpg`（六宫格，留 10 张）、`output/det_*_vis/_ir.jpg`（成对，留 10 对）。

### 4.3 模型与标定

- 模型 `yolov8m_rv1126b.rknn`（INT8 量化，640×640 输入）来自 `yolov8_detect_C_demo/yolov8_detect_demo_release/`，`deploy.sh` 自动 scp；
- dual_demo 配准：无 `calibration.txt` 时自动退化为 FOV 缩放（3 倍 margin 吸收偏差，不影响 FAR）；相机被动过之后用 `twocameraOnMAC/test/camera_capture_test/calib_web.py` 网页选 ≥4 对同名点重标定。

## 5. ★ 红外摄像头：编译平台与 SDK 库特性（重点）

红外部分是**厂商闭源 SDK**，与普通 UVC 摄像头有本质区别，编译与部署必须理解以下特性。

### 5.1 库组成、平台与来源

`libs/arm64/`（根目录与 dual_demo 各一份）内全部为 **ELF64 / AArch64**（`readelf -h` 确认），只支持在 RV1126B（aarch64）上运行：

| 文件 | 大小 | 版本 | 说明 |
|---|---|---|---|
| `libiruvc.so` | 337 KB | **2.0.1** | USB 拉流，NEEDED：libusb-1.0.so.0、libc |
| `libirparse.so` | 28 KB | 1.0.0 | 帧解析（raw_data_cut 组合流切分） |
| `libirprocess.so` | 43 KB | 0.8.3 | 图像处理（YUYV→RGB 等） |
| `libusb-1.0.so.0` | 145 KB | 1.0.2.0 | **SDK 自带**，避免依赖板端 libusb |

- 来源：`twocameraOnMAC/test/camera_capture_test/build/libs/`（ARM 环境构建时留下的 aarch64 备份）；注意 `twocameraOnMAC/libs/native/` 下的同名库是 **x86-64**，不能用；
- 本项目链接的是**旧版 `uvc_camera_*` API**（新版库已重命名为 `iruvc_camera_*`，与头文件不兼容，勿混用）；
- CMake 通过 `link_directories(libs/arm64)` 链接 `iruvc irparse irprocess`，`RPATH = $ORIGIN/../libs/arm64`（build 与 install 均设置），部署后免 `LD_LIBRARY_PATH`；
- 本项目未链接 `libirtemp`——温度换算为手写常量（`ir_temp_conf.h`：`IR_TEMP_LSB_PER_K=64.0`，`IR_TEMP_K_OFFSET=273.15`）。

### 5.2 闭源 SDK 的运行时特性

| 特性 | 说明 |
|---|---|
| **绕过内核 V4L2** | 红外虽暴露标准 UVC 节点（YUYV 256×192@25），但**不能**用 V4L2 读；SDK 经 libusb 直接 claim 原始 USB 设备，dmesg 报 `did not claim interface 0 before use` |
| **带宽统计旁路** | libusb 的 isoc URB 不计入内核 `Alloc` 带宽统计（`/sys/kernel/debug/usb/devices` 显示 0% 但实际占用） |
| **组合流协商** | SDK 只能协商 **256×384 YUY2**（image+temp 上下拼接），协商单 256×192 流时 `uvc_frame_get` 返回空帧；由 `raw_data_cut` 切出上半段 256×192 图像，实际占用约 4.9MB/s |
| **真实测温（情形 A）** | 下半段为 Y16 定点温度矩阵，`℃ = raw/64 − 273.15`；板端实测帧中位数 38.97℃、范围 18.35~56.72℃，符合室内场景（见探针报告） |
| **NUC/增益坏帧** | 约 30% 帧为整帧极端值（raw ~341 → −267.8℃ 或 ~62837 → +708.7℃，NUC 快门/自动增益瞬态）；工程处置：帧级门禁（min<−60℃ 或 max>200℃ 直接丢弃）、探针统计用帧中位数、NUC 冻结检测用于降级 |
| **固件与校正表** | `RS001_FW_new.bin`（模组固件）、`tau_H.bin` / `tau_L.bin` / `new_tau_H.bin`（高/低增益校正表）在 SDK 打开设备时下发，**必须随程序部署**（`firmware/` 目录） |
| **权限** | root 直接运行无问题（板端以 root 登录）；非 root 需对 `0bda:5840` 原始 USB 设备授权（udev 规则，参考 `twocameraOnMAC/udev/70-twocamera.rules`） |
| **彻底关流** | 关闭必须用 `uvc_camera_stream_close(CLOSE_CAM_SIDE_PREVIEW)` 并按序 `uvc_camera_close/release`，否则残留等时带宽 ghost reservation 导致后续 STREAMON 报 ENOSPC；掉线恢复时须确认 SDK 已 `close()` 释放 USB claim 再重枚举 |

### 5.3 USB 带宽约束（历史教训，见 USB带宽约束分析.md）

- **曾经的问题**：早期两相机与网卡同挂唯一 EHCI USB2.0 总线（等时预算 48MB/s），红外 SDK 启动后可见光 `VIDIOC_STREAMON` 报 `ENOSPC`——三重硬约束：①USB2.0 预算上限；②可见光相机 UVC 描述符只有 alt 1（固定预留 24.576MB/s，无法降）；③红外 SDK 闭源、alt 协商不可控且绕过内核统计。降分辨率/帧率均无效，软件层已穷尽。
- **最终解决**：用户将两相机**分到两个独立 USB 控制器**（红外 Bus 001 USB2.0、可见光 Bus 004），带宽争抢消除，双路可同时 25fps 全速运行。
- 遗留纪律：仍默认 `ir-first` 启动顺序、彻底关流、分辨率档位自动降级链（`--res-preset auto`：1280×960 → 1024×768 → 1280×720 → 800×600 → 640×480）——**双路 5 分钟帧率稳定（IR ≥24.5 / VIS ≥ 目标×0.98 / skip_align<1%）是所有指标可信的前提，不达标降一档，不要硬扛**。
