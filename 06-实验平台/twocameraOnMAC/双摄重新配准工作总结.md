# 双摄重新配准工作总结

> 场景：两个摄像头（红外 + 可见光）**被动过、重新安装或支架位置重新固定后**，双摄几何关系改变，原配准参数失效，必须重新标定。
>
> 依据：[camerayolo.md](camerayolo.md) §3.2 图像配准设计、[image_registrator.h](src/image_registrator.h)/[image_registrator.cpp](src/image_registrator.cpp)、[calib_web.py](test/camera_capture_test/calib_web.py)、[camera_capture_test/main.cpp](test/camera_capture_test/main.cpp)、[calibration.txt](calibration.txt)。

---

## 1. 为什么要重新配准

- 主程序用 `ImageRegistrator` 把**可见光帧对齐到红外视角**（IR 帧不参与配准），对齐结果同时供 YOLO 检测与并排显示使用；
- 配准参数全部来自项目根目录 `calibration.txt`（红外视野在可见光画面中的四边形 quad），**与相机的物理安装位姿一一绑定**；
- 相机一旦挪动/重装，quad 就不再对应红外真实视野 → 可见光画面与红外错位 → 双模态检测（YOLOFuse 6ch 输入）与叠加显示全部失真。此时只需重新标定，**无需改任何代码或重新编译**。

## 2. 配准机制回顾（标定前须知）

| 项 | 说明 |
|---|---|
| 模式 A（默认） | 轴对齐 crop+resize：按 `REGISTRATION_CROP_*` 宏（`sample_config.h`）裁剪可见光中心区域缩放到 IR 分辨率，不依赖标定文件 |
| 模式 B（标定后启用） | 四边形透视截取：quad 4 顶点 → 单应矩阵（4 点 DLT，`h33=1`），逐像素双线性采样映射到 IR 分辨率，越界补黑 |
| 方向约定 | **可见光 → 红外视角**；quad 是"红外视野在可见光画面（640×480）中的四边形"，顶点顺序 0=左上 1=右上 2=右下 3=左下（对应红外画面四角） |
| 分辨率适配 | quad 坐标基于 640×480；可见光采集分辨率变化时程序自动等比换算（`image_registrator.cpp`） |
| 加载时机 | 主程序启动时读取 `calibration.txt`，保存后**下次启动自动生效** |

## 3. 重新配准完整流程（四步）

### Step 0：重拍标定图对（camera_capture_test）

拍照工具源码：[test/camera_capture_test/main.cpp](test/camera_capture_test/main.cpp)，采集链路与主程序 sample.cpp 完全一致（`IrCamera` + `VisibleCamera` + `LatestFrameSynchronizer`）。

#### 0.1 编译

```bash
cd test/camera_capture_test
./build.sh                    # native g++ 编译, 输出 build/camera_capture_test
./build.sh clean              # 清理构建目录
# SDK 库目录默认 /mnt/hgfs/share/code/linux_ac010/aarch64-linux-gnu_libs,
# 需要时覆盖: IR_SDK_LIB_DIR=/path/to/libs ./build.sh
```

> build.sh 在 hgfs 共享盘上强制单线程编译（规避 `.o` 截断问题），与顶层 Makefile 行为一致。

#### 0.2 运行与操作

```bash
# 必须在项目根目录运行(captures/ 输出路径是相对路径):
cd /path/to/twocameraOnMAC
test/camera_capture_test/build/camera_capture_test
```

程序启动后自动依次执行：

1. 打开红外相机（SDK，默认配置：**不开镜像/旋转/伪彩**，保证标定用原始图像）；
2. **先启动红外 ISO 流，再开可见光 V4L2**（与主程序相同的启动顺序，避免可见光抢占 USB 等时带宽导致红外启动阻塞）；
3. 可见光以 **MJPG 640×480@30** 打开（与主程序一致，保证标定坐标与运行时同尺度）；
4. 自动创建 `captures/images/`、`captures/imagesIR/`（不存在时）。

预览窗口（`calib-capture`）为横向拼接：**左=可见光原始帧，右=红外放大到同高预览**（仅显示用，保存的仍是原始 256×192）；左上角实时显示已保存对数。

| 按键 | 动作 |
|---|---|
| **Enter / 空格** | 拍照：保存 `LatestFrameSynchronizer` 同步后的**同一时刻**可见光+红外成对图像 |
| `q` / `Q` / `Esc` / 关闭窗口 / Ctrl+C | 退出（已保存的图不受影响） |

#### 0.3 保存位置与编号规则

- `captures/images/NNN.jpg` — 可见光原始帧（640×480），与 YOLOFuse 数据集 `images/` 结构一致；
- `captures/imagesIR/NNN.jpg` — 红外原始帧（256×192），对应 YOLOFuse `imagesIR/`；
- 编号 `NNN` 从 000 起自动寻找**第一个未占用编号**续拍（中断后重开不覆盖旧图）；若想全新开始，先备份/清空这两个目录。

#### 0.4 拍摄要求（决定标定精度）

- **先固定相机再拍**：拍摄过程中相机位姿不能再动，拍完的图才代表"确定位置后"的几何关系；
- 取 **4~8 对图、特征点覆盖画面四角**（quad 外沿精度由边缘点决定）；
- 场景中要有红外/可见光都清晰可辨的角点（人、灯具、门框角、发热物体边缘等），避免选纯色/反光/运动模糊区域；
- 双摄视角差异大时，优先保证 **4 个画面角附近各有一对清晰对应点**。

### Step 1：启动网页标定工具（calib_web.py）

```bash
python3 test/camera_capture_test/calib_web.py              # 自动开浏览器 http://localhost:8765
python3 test/camera_capture_test/calib_web.py --port 9000 --no-browser
python3 test/camera_capture_test/calib_web.py --test       # 内置算法自检
```

- 零第三方依赖（纯 Python 标准库），自动加载 `captures/images/*.jpg`（IR 图按 `images/` → `imagesIR/` 同名规则取）；
- 无图对时报错退出，先完成 Step 0。

### Step 2：Tab 1「选点标定」——粗标定

1. 翻到一组图对，在 **RGB 图上点一个特征点 → 再在 IR 图上点同一物理位置**，即得 1 对点（红点=待配 IR，绿点=已成对；右键/撤销按钮可回退）；
2. 至少 **4 对**（建议 4~8 对、覆盖四角）→ 点「计算」；
3. 工具用最小二乘 DLT 求解 IR→RGB 单应，输出：
   - **红外视野四边形**（RGB 坐标，自动叠加显示在 RGB 图上，青色多边形）；
   - 每对点残差表（**残差 >5px 标红**，建议撤销该点重选）；`max_err` 越小越好（现行标定文件为 2026-08-29 生成，max_err=0px，4 点恰好定解）；
4. 结果自动同步到 Tab 2。

### Step 3：Tab 2「画面截取」——拖点精调

- 左侧大图上**直接拖动 4 个绿色顶点**（四边形外的可见光区域被暗化=将被丢弃）；
- 右侧实时预览"四边形内可见光内容变换到红外视角 (256×192)"与红外原图的对比，三种模式：
  - **叠加**（半透明混合）、只看红外 / 只看截取结果；
  - **闪烁对比**（勾选后 700ms 交替，对错位最敏感，推荐收尾用）；
- 拖到两画面**完全重合**为止；「重置为标定四边形」可回到 Step 2 计算结果；
- 底部输出框实时显示 quad 顶点、变换矩阵 H、**越界黑边占比**（黑边过大说明 quad 偏小，可适当外扩）。

### Step 4：保存生效

- 点「保存到 calibration.txt」→ 写入项目根目录（含生成时间/来源注释）；
- 重启主程序 `make run` / `./build/run.sh` 即自动加载，**无需重编译**；
- 验收：并排显示中同一物体在 IR/可见光两半画面位置一致；YOLOFuse 模式下双模态框基本重合。

## 4. 什么时候需要重新标定（触发条件清单）

| 触发条件 | 说明 |
|---|---|
| 相机被挪动/重装/支架重新固定 | 本文档主场景 |
| 更换任一相机 | 新相机 FOV/安装位不同 |
| 可见光变焦/对焦机械调整 | 视场变化即失效 |
| quad 出现明显黑边或截取不全 | 拖点时外扩不足，重新精调 |
| 红外开窗/数字变焦设置变化 | IR 视野四角映射关系改变 |

> 无标定文件时程序回退 `REGISTRATION_CROP_*` 宏（轴对齐 crop+resize），仅适用于双摄光轴大致平行、仅 FOV 不同的粗对齐场景。

## 5. 与设计文档的对应关系

- [camerayolo.md](camerayolo.md) §3.2 的**标定流程设想**是"棋盘格 + `stereoCalibrate` 双目外参 + `calibration.json`"；
- **实际落地**更轻：网页选点/拖点 → 4 点单应 → `calibration.txt`（纯文本 quad 一行），去掉了棋盘格与双目外参环节；
- §3.2 的配准方式对比（crop+resize / warpPerspective / 自适应特征匹配）中，最终实现的是前两者的组合：crop+resize（模式 A）+ 四边形透视（模式 B，本质是限定在 quad 内的 warpPerspective）；自适应 ORB 方案未采用（避免每帧特征匹配的 CPU 开销）。
