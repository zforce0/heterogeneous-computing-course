# twocameraOnMAC 项目总结

> 双摄像头（红外热像 + 可见光）实时采集 + YOLO 目标检测 + ByteTrack 多目标跟踪 + 伪彩叠加，本机（aarch64 Ubuntu）OpenCV 显示。
>
> 本文档综合 [README.md](README.md)、[camerayolo.md](camerayolo.md)（集成方案与架构设计）、[202608201547.md](202608201547.md)（aarch64 原生编译实测）等文档整理。

---

## 1. 项目功能

### 1.1 一句话定位

在 aarch64 Ubuntu 本机上，同时采集**红外热像模组**（256×192，厂商闭源 SDK / libusb）与**可见光 USB 相机**（640×480，V4L2 MJPG），完成时间同步、图像配准、YOLO 推理、多目标跟踪，并将双画面并排合成后实时显示。

### 1.2 处理管线

```
IrCamera (USB SDK, 256×192)  ─┐
                               ├→ Synchronizer → ImageRegistrator → IDetector (ONNX Runtime)
VisibleCamera (V4L2, 640×480) ─┘      (时间同步)     (crop+resize 配准)        ↓
                                                              ByteTrack 多目标跟踪
                                                                        ↓
                                    SideBySideCompositor → TrackingOverlay → OpenCV 显示
                                    (双画面并排 1:1 等大)   (检测框+跟踪ID+运动箭头
                                                            +轨迹+IR框内伪彩
                                                            +可见光框内半透明伪彩)
```

### 1.3 核心能力

| 能力 | 说明 |
|---|---|
| 双路采集 | IR 经闭源 SDK（libusb 直连 USB，不走 V4L2）；可见光走标准 V4L2 MJPG/YUYV，按 VID/PID 自动探测节点 |
| 时间同步 | `LatestFrameSynchronizer` 取两路最新帧（`SyncedFrames`） |
| 图像配准 | `ImageRegistrator` 把可见光帧对齐到 IR 视角；优先读 `calibration.txt`（`test/camera_capture_test/calib_web.py` 网页标定产出），无标定时用 `REGISTRATION_CROP_*` 宏兜底 |
| YOLO 检测 | 两种后端经 `sample_config.h` 的 `DETECTOR_BACKEND_YOLOV8N` 切换：<br>`1` = YOLOv8n 可见光人像（CrowdHuman 训练，3ch letterbox，`models/yolov8n/yolov8n_person.onnx`，当前默认）<br>`0` = YOLOFuse 双模态融合（IR+RGB 6ch 拼接输入 `[1,6,640,640]`，IR 前 3 通道，`models/best.onnx`） |
| 多目标跟踪 | C++ 原生 ByteTrack（Kalman 滤波 + Hungarian 匹配，约 500 行，无 Python 依赖），输出跟踪 ID、速度向量、历史轨迹 |
| 伪彩叠加 | IR 子画面检测框内完整 JET 伪彩（热力图）；可见光子画面框内半透明伪彩（alpha=0.5，OpenCV applyColorMap/addWeighted） |
| 运动意图 | 框底部运动方向箭头（长度∝速度，颜色按速度分级：灰/绿/黄/红）+ 轨迹路径折线 |
| 新目标提示音 | `AlertNotifier`：新目标稳定存在超过 `NEW_TARGET_STABLE_MS`（1000ms）播放 880Hz/120ms 短音；dlopen ALSA，无链接期依赖，防抖 500ms |
| 帧率叠加 | 合成画面上绘制两路实时 FPS（EMA 平滑） |
| 测温 | `TemperatureFrame` 输出 Y16 温度矩阵（`copy_latest_temperature`），测温演示宏 `POINT/LINE/RECT_TEMP_DEMO` 默认关闭 |

### 1.4 显示与运行模式

- 默认后端 `OPENCV`（imshow 弹窗）；备选 `FBDEV`（framebuffer 直写，为无 X 环境的嵌入式部署预留）。
- 布局为**并排等大**（IR 与可见光各占一半、统一高度、保持各自 4:3 宽高比，分割线宽 `LAYOUT_GAP_WIDTH=4`）；旧 PiP 画中画实现 `frame_compositor.*` 保留源码但不编译。
- 运行时长由 `STREAM_TIME_SECONDS` 控制（当前 600 秒后自动退出；Ctrl+C / 关窗口 / `q` / `Esc` 亦可退出）。

## 3. 本地编译与启动（aarch64 Ubuntu）

### 3.1 依赖

| 依赖 | 说明 |
|---|---|
| 红外 SDK（aarch64） | `/mnt/hgfs/share/code/linux_ac010/aarch64-linux-gnu_libs`（Makefile 默认；详见 §5） |
| ONNX Runtime (aarch64) | `/tmp/onnxruntime-linux-aarch64-1.21.0`（YOLO 检测需要） |
| OpenCV | `core highgui` 组件（本机实测 4.10.0） |
| libjpeg | 可见光 MJPG 解码（系统安装即可） |
| 工具链 | cmake / g++ / make / pkg-config |

安装依赖：

```bash
sudo apt-get update && sudo apt-get install -y --no-install-recommends \
  cmake g++ make pkg-config libopencv-dev libjpeg-dev v4l-utils
```

### 3.2 编译

```bash
make native                        # 默认启用 YOLO 检测
make native YOLO_CMAKE_ARGS=       # 纯采集预览（无检测，不需要 ONNX Runtime）

# 等价的直接 cmake 方式：
cmake -S . -B build/native \
    -DTWOCAMERA_SDK_LIB_DIR=/mnt/hgfs/share/code/linux_ac010/aarch64-linux-gnu_libs \
    -DTWOCAMERA_ENABLE_YOLO=ON \
    -DTWOCAMERA_ONNXRUNTIME_DIR=/tmp/onnxruntime-linux-aarch64-1.21.0
cmake --build build/native
```

- 产物：`build/native/sample`；SDK `.so` 自动拷贝到 `build/native/libs/`，固件 `.bin` 自动拷贝到产物目录，rpath 已配置（`$ORIGIN/libs`），无需 `LD_LIBRARY_PATH`。
- ⚠️ 源码在 hgfs（vmhgfs-fuse）上时，**并行构建偶发 `.o` 文件截断**（`file too short` 链接错误），删除损坏 `.o` 后改用单线程构建：`cmake --build build/native --parallel 1`（见 202608201547.md §4.2）。

### 3.3 启动

```bash
./build/run.sh                     # 一键：编译(增量) + 启动
NO_YOLO=1 ./build/run.sh           # 纯采集模式
./build/run.sh --visible /dev/video1

# 或直接运行（需在项目根目录，模型为相对路径）：
make run
./build/native/sample
```

常用参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--visible PATH` | 自动探测 1d6c:0103 | 可见光相机节点 |
| `--width/--height/--fps` | 640/480/30 | 可见光采集参数（MJPG） |

### 3.4 USB 权限

红外相机走 libusb 直连，普通用户需安装 udev 规则并重新插拔：

```bash
sudo cp udev/70-twocamera.rules /etc/udev/rules.d/
sudo udevadm control --reload && sudo udevadm trigger

# 临时授权（设备号随重插变化）：
sudo chmod 666 /dev/bus/usb/001/010 /dev/bus/usb/001/011
```

### 3.5 关键编译期配置（src/sample_config.h）

- 红外流模式三选一：`IMAGE_AND_TEMP_OUTPUT`（当前启用）/ `IMAGE_OUTPUT` / `TEMP_OUTPUT`；
- 检测后端：`DETECTOR_BACKEND_YOLOV8N`（1=YOLOv8n 人像，0=YOLOFuse 双模态）；
- 跟踪/伪彩/提示音/帧率叠加均有独立开关宏；
- `STREAM_TIME_SECONDS`：程序自动退出时长。

### 3.6 测试

```bash
cd test/detector_test && ./build.sh && ./build/detector_test   # LLVIP 图离线验证推理+画框
```

## 4. RV1126B 上的启动

本项目本体**在 RV1126B 上没有已落地的直接运行版本**，但两条路径都指向它：

1. **规划路径（camerayolo.md 阶段三）**：在本项目基础上做 RV1126B 交叉编译 + RKNN 部署——
   - 模型：`best.pt → best.onnx → best.rknn`（x86 PC 用 rknn-toolkit2 做 INT8 量化，`target_platform='rv1126'`）；
   - 推理：新增 `detector_rknn.cpp` 实现 `IDetector` 接口（`rknn_init/rknn_inputs_set/rknn_run/rknn_outputs_get`）；
   - 构建：`cmake -B build/rv1126 -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/rv1126-toolchain.cmake -DTWOCAMERA_DISPLAY_BACKEND=FBDEV -DTWOCAMERA_YOLO_BACKEND=RKNN ...`（工具链文件需自建）；
   - 显示：FBDEV / SPI 屏（LVGL + ILI9341），RGA 硬件做配准缩放，异步推理三线程模型。
2. **实际落地路径（姊妹项目 rv1126_test）**：RV1126B 板端的双相机 + YOLOv8 RKNN 推理已在 `rv1126_test` 项目中实现。它直接复用了本项目的 `visible_camera`、`mjpeg_decoder`、`ir_camera` 模块与 aarch64 闭源 SDK 库（取自本项目 `test/camera_capture_test/build/libs/` 备份）。板端启动方法见该项目的文档（`deploy.sh` 同步源码到板端 → 板端 `build.sh` 编译 → `run.sh` 启动）。

> 红外 SDK 在 RV1126B（aarch64）上验证可用：库为 ELF64/AArch64，板端以 root 运行无需 udev 规则；固件与校正表须随程序部署。

## 5. ★ 红外摄像头：编译平台与 SDK 库特性（重点）

红外部分是**厂商闭源 SDK**，与普通 UVC 摄像头有本质区别，编译与部署必须理解以下特性。

### 5.1 库组成与版本（libs_version.txt）

| 库 | 版本 | 职责 |
|---|---|---|
| `libiruvc` | 2.0.1 | USB 拉流（内部经 libusb 直连设备） |
| `libirparse` | 1.0.0 | 帧解析（raw_data_cut 切分组合流） |
| `libirprocess` | 0.8.3 | 图像处理（YUYV→RGB、增益、几何变换） |
| `libirtemp` | 1.0.0 | 测温（配合 tau 校正表） |
| `libusb-1.0.so.0` | 1.0.2.0 | SDK 自带，避免依赖系统 libusb |

头文件位于 `include/`（libiruvc.h 等 6 个）。

### 5.2 平台/架构矩阵（编译前必查，踩坑记录见 202608201547.md）

| 目录 | 架构 | API 版本 | 结论 |
|---|---|---|---|
| `libs/native/`（项目自带） | **x86-64** | 旧版 `uvc_camera_*` | 供 x86/Mac 主机；aarch64 本机**不能用** |
| `/mnt/hgfs/share/code/linux_ac010/aarch64-linux-gnu_libs`（Makefile 默认） | **aarch64** | 旧版 `uvc_camera_*`（11/11 导出符号齐全） | ✅ **本机 aarch64 编译用这套** |
| `../cross_compile_libs/aarch64-linux-gnu_libs` | aarch64 | **新版 `iruvc_camera_*`（API 重命名）** | ❌ 与本项目头文件不兼容，链接全挂 |
| `../linux_ac010/aarch64-v01c01-linux-musl_libs` | aarch64/musl | — | ❌ 与 Ubuntu glibc 不匹配 |
| `test/camera_capture_test/build/libs/` | **aarch64** | 旧版 | ✅ 备份（rv1126_test 的 `libs/arm64/` 即源于此） |

判定方法：`file` 看架构 + `nm -D --defined-only` 看导出符号。本项目源码（`include/libiruvc.h`）期望的是**旧版 API**（`uvc_camera_open` / `uvc_camera_stream_start` / `libiruvc_version` 等）。

### 5.3 闭源 SDK 的运行时特性

| 特性 | 说明 |
|---|---|
| **绕过内核 V4L2** | 红外设备虽然暴露标准 UVC 节点（YUYV 256×192@25），但**不能**用 V4L2 直接读；SDK 经 libusb 直接 claim 原始 USB 设备，dmesg 会出现 `did not claim interface 0 before use` 警告 |
| **带宽统计旁路** | libusb 提交的 isoc URB 不计入内核 `Alloc` 带宽统计（`/sys/kernel/debug/usb/devices` 显示 0% 但实际占用），多流并发时容易误判 |
| **组合流协商** | SDK 只能协商 **256×384 YUY2**（图像 + 温度上下拼接）；协商单 256×192 流时 `uvc_frame_get` 返回空帧。由 SDK `raw_data_cut` 切出上半段 256×192 图像 |
| **温度数据** | 组合流下半段为 Y16 定点温度矩阵：`温度(℃) = raw / 64.0 − 273.15`（K×64 编码），换算实现见 `src/temperature.cpp` |
| **固件与校正表** | `RS001_FW_new.bin`（模组固件）、`tau_H.bin` / `tau_L.bin` / `new_tau_H.bin`（高/低增益校正表）在 SDK 打开设备时下发，**必须随程序部署**（CMake POST_BUILD 自动拷贝到产物目录；路径宏在 `sample_config.h` 的 `FIRMWARE_FILE_PATH` 等） |
| **流模式宏** | `IMAGE_AND_TEMP_OUTPUT` / `IMAGE_OUTPUT` / `TEMP_OUTPUT` 三选一（编译期），同时控制 `ir_camera.h` 中 `IrStreamMode` 的默认值 |
| **采集模式** | 默认 polling（`uvc_camera_stream_start(cam, NULL)` + 独立采集线程）；预留 `sdk_callback_mode`（`uvc_camera_stream_start(cam, &callback)`），两者启动顺序/关闭行为略有差异 |
| **启动顺序** | 与可见光共用 USB 总线时**必须先启动红外 ISO 流，再开可见光 V4L2**，否则可见光先占满等时带宽导致 `uvc_camera_stream_start` 阻塞/失败 |
| **彻底关流** | 关闭必须用 `uvc_camera_stream_close(CLOSE_CAM_SIDE_PREVIEW)` 并按序 `uvc_camera_close/release`，实测可彻底释放等时带宽（Alloc 归零），否则残留 ghost reservation 会让后续 STREAMON 报 ENOSPC |
| **权限** | libusb 需对 `0bda:5840` 原始 USB 设备的读写权限：root 直接可用；普通用户装 `udev/70-twocamera.rules`（MODE=0660 + plugdev 组） |

### 5.4 设备身份（易混淆点）

| VID:PID | 身份 | 采集方式 |
|---|---|---|
| `0bda:5840`（Realtek USB Camera） | **红外热像** | SDK libusb 直连（不走 V4L2） |
| `1d6c:0103`（webcamproduct） | 可见光 | 标准 V4L2（MJPG 1920×1080 顶格，常用 640×480@30） |

> 曾误把 `1d6c:0103` 填给红外 SDK，结果 SDK 列出 1920×1080 MJPG/H264（可见光规格）——由 SDK 列流格式反推确认 `0x0BDA/0x5840` 才是红外（`ir_camera.h` 的 `IrCameraConfig` 默认值即正确，勿改）。

### 5.5 CMake 集成要点

- `TWOCAMERA_SDK_LIB_DIR` 指定 SDK 库目录，CMake 用 `find_library` 定位 `iruvc/irtemp/irprocess/irparse/usb-1.0` 五个库；
- `POST_BUILD` 自动把 `*.so`、`*.so.*` 拷到 `build/native/libs/`，把固件/校正表 `.bin` 拷到产物目录；
- `BUILD_RPATH = $ORIGIN/libs;${SDK_DIR};${ONNXRUNTIME_DIR}/lib`，产物免环境变量直接运行；
- 可见光 MJPG 解码依赖 libjpeg（`TWOCAMERA_NO_JPEG=ON` 可切 YUYV 模式规避该依赖）。
