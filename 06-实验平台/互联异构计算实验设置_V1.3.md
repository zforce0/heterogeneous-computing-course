### 2.2 NPU 后端尝试：**编译成功，运行时不可用**（如实记录）

CANN 版 `llama-server` 编译成功，`--list-devices` 正确返回 `CANN0: Ascend310B1 (23673 MiB, 19456 MiB free)`，权重可 offload 到 NPU。但连续 4 个 310B1 专属阻塞点，前 3 个已绕过，第 4 个是算子库硬限制：

1. `GGML_ASSERT(ptr % TENSOR_ALIGNMENT == 0)` → `GGML_CANN_NO_PINNED=1`
2. `EZ9903 support for Ascend310B is not implemented`（VMM） → `GGML_CANN_MEM_POOL=leg`
3. `aclnnCalculateMatmulWeightSizeV2` 未实现（NZ 权重重排） → `GGML_CANN_WEIGHT_NZ=off`
4. **`EZ1001: binary_info_config.json of socVersion [ascend310b] does not support opType [RmsNorm]`** → 无开关可绕，qwen3 每层强依赖 RMSNorm，**终止**

源码侧还打了 3 处兼容补丁（2 个 8.0.RC3 不存在的头文件、1 个训练期 loss 算子、supports_op 排除 CROSS_ENTROPY_LOSS）。llama.cpp 官方 CANN 后端验证机型仅 910B/910C/310P，**310B1 不在列表**。

**结论：生产服务固定使用盒上 ARM CPU 后端**，不把「编译成功」冒充「NPU 推理成功」。完整日志、补丁位置与升级路径见 `…/npu_attempt.md`。

### 2.4 RV1126B：✅ 在线（2026-11-16 复测，硬件完好）

**此前"离线"不是硬件故障，是地址问题。** 板子为 `EASY-EAI-NANO-TB`（Rockchip RV1126B NANO V10，4 核 aarch64 / 1968 MB / kernel 6.1.141，MAC `4e:0e:39:be:41:b3`），netplan 里 `eth0`（NET0）是 `dhcp4: true`，而静态 `.22` 原本配在 `eth1`（NET1）。网线插在 NET0 时，实验室网段没有 DHCP 服务器 → 板子拿不到地址、二层零流量，所以 ARP 与全网段扫描都看不到它，表现为"灯亮着但像死了"。旁证：板端 `camera-preview.service` 因绑定 `192.168.77.22` 失败，累计重启 **65 840 次**。

定位手法：在 RK3588 上临时起 dnsmasq 作 DHCP 服务器，板子续租时的 `DHCPDISCOVER` 立刻带出主机名与 MAC。**无 IP 的设备只有 DHCP 能召唤出来。**

已修复并验证：
- `eth0` 改为静态 `192.168.77.22/24`（`dhcp4: false`），`eth1` 去掉重复静态地址，原配置备份为 `*.bak.20261116`；`netplan apply` 后**重启整机**，重启后 `uptime 0 min` 即带静态地址，SSH 免密可用；
- RK3588 上新增 systemd 兜底服务 `g4-dhcp.service`（仅 eth1、不做 DNS、RV MAC → `.22` 无限期、其它设备 `.150-.170`），板子万一被重刷回 DHCP 也能自动拿回原地址；
- 实测：`ping .22` RTT **1.28 ms**；`8082` 视觉服务在线，可见光 **10 fps**（3 s 涨 31 帧），YOLO 检出 mouse 0.784 / chair 0.783，`/vis.jpg` 画面清晰。

**遗留：热成像（IR）未就绪。** 厂商 SDK `/root/eval_dashboard/ir_snap` 报 `IR camera 0bda:5840 was not found`，`lsusb` 中确无该设备（只有可见光 `1d6c:0103` 与 RTL8153 网卡）——属**物理连接**问题，需检查热成像模组的 USB 线；插好后再跑 `./ir_snap` 与 `/status.json` 复验 `ir_ready`。

端侧视觉脚本 `run_g4_pipeline.sh rv` 现可直接执行；dashboard 中 4 组关键帧仍是 **2026-10-12 归档实跑**（标注 `archived`），待热成像恢复后可采 fresh 成对帧。

## 3. Dashboard（V2 实时交互版）

- 页面：`eval_platform/dashboard/g4_live.html`（49 KB，图像走 URL 引用，不再 base64 内嵌）
- 服务：`python3 eval_platform/dashboard/serve_g4.py --port 8899` → **http://127.0.0.1:8899/**
- 实时层：
  - `GET /api/stream`：**SSE**，每 2 s 推送四节点探测（含 RTT/端口）、RV1126B status.json、llama-server Prometheus 指标与事件流
  - `GET /stream/vis.mjpg` `/stream/ir.mjpg`：**MJPEG 实时视频**（约 8 fps，服务端共享帧缓存，多客户端复用）
  - `POST /api/llm/stream`：**流式对话**，逐 token 回传，结束带 `timings.predicted_per_second`
  - `GET /api/snapshot?kind=vis|ir`：一键把当前帧存进 `samples/`（存证）
  - `GET /api/control?action=start|pause|stop`：代理 RV1126B 视觉服务开关
  - `POST /api/bench`：现场跑 3 条用例实测吞吐
- 交互：点节点看详情、关键帧灯箱、可见光/热成像切换、检测框叠加、实时曲线（RTT/帧率/吞吐）、事件流、Toast
- **拓扑自动发现**（2026-11-18 新增）：
  - 采集器：`eval_platform/tools/discover_topology.py`（可独立 CLI：`--json` / `--write`）
  - `GET /api/topology`：返回四台设备的**逐网口实测数据**（接口名、MAC、载波、速率、MTU、driver、sysfs 总线、IPv4）+ 链路 + 形状判定 + 口径限制；服务端 60 s 缓存、后台每 30 s 检查过期
  - 连接方式判定：`driver` 名 + `sysfs` 总线类型，例：`r8152`+`usb` → USB 转以太网；`hns3-platform`/`rk_gmac-dwmac`+`platform` → SoC 板载 GMAC；macOS 侧读 `networksetup -listallhardwareports` 的硬件端口名（`AX88179B` → USB 转以太网）
  - 页面按实测数据**动态生成 SVG**（不再硬编码坐标）：节点卡片显示实验口 + 介质 + 速率，链路标签显示 `ifname · 速率`；离线/无载波画虚线，有载波但无实验地址的闲置口单独标黄
  - 下方「接口自动识别」表逐口列出证据字段与判定依据，并列出形状判定依据与限制
- `/api/status`（旧）：一次性探测，保留向后兼容
- 生成器：`python3 eval_platform/dashboard/build_g4_dashboard.py`（读实测 JSON 重建页面）
- 注：昇腾 `llama_server.sh` 已加 `--metrics`，故能取到真实 token 吞吐；空闲时 gauge 为 0，页面显示 `--` 而非 0.0
- 口径：交换机不可管理（无 SSH/SNMP/LLDP），**「设备→交换机端口号」无法读取**，连线对端一律标 `inferred`；形状由「是否有 bridge / ip_forward / 多载波口」+ 可达性推断，断开时降级为 `unknown` 而非硬报 star

## 5. 遗留项与口径

1. **RV1126B 热成像模组接线** —— 板子已在线（SSH 免密、视觉 10 fps）；仅剩热成像 USB 未枚举（`0bda:5840` 缺失），插好后复验 `ir_ready` 即可采 fresh 成对关键帧。
2. **昇腾 `.10` 已固化** —— NetworkManager keyfile 写死双地址 `192.168.137.100/24 + 192.168.77.10/24`（`persist_ascend_lab_ip.sh`），重启不丢；出厂地址保留用于跳板。
3. **NPU 未启用** —— 需升级 CANN 到提供 `ascend310b` RmsNorm 算子的版本，或改用 MindIE；见 `npu_attempt.md`。
4. **模型规格偏小** —— 0.6B 是为在 4× TAISHAN @1.6 GHz 上取得可用延迟而选；盒子有 24 GB，若 NPU 打通可换 7B 级。
5. **板钟漂移** —— 昇腾盒子落后约 15 个月（显示 `2025-08-15`），跨设备协同仍以单调钟 + RTT 建期限。
6. **Mac 的 Ollama** 保留安装但已退役，不作为实验 LLM 节点；`serve_lan.sh` 与 `bench_llm.py` 为 V1.2 历史基线。

**测量口径**：本实验一律以实机命令输出为准，未验证项标 `planned` / `N/A`；ping 判定用 RTT 行或退出码，不用 `0.0% packet loss` 子串（历史上曾因 `100.0%` 误报）。
